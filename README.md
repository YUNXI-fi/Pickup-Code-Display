# 取件码展示（Pickup Code Display）

> 一款面向飞牛 fnOS 的快递取件码管理系统，支持**手动录入**、**AI 拍照识别**与**淘宝 / 拼多多订单自动采集**，提供实时大屏展示、分组视图与状态管理，适用于驿站、代收点等场景。

- 应用标识：`pickup.codes`
- 当前版本：`1.2.3`
- 开源仓库：[YUNXI-fi/Pickup-Code-Display](https://github.com/YUNXI-fi/Pickup-Code-Display)
- 维护者：YUNXI

## 核心功能

### 📦 取件码管理

- **手动录入**：填写取件码、快递公司、收件人、手机尾号、取件地址，一键添加
- **AI 识别录入**：上传快递面单照片，自动识别取件码、快递公司与取件地址（基于 SiliconFlow 视觉大模型）
- **历史自动补全**：录入收件人 / 手机尾号 / 取件地址时，自动联想历史记录，减少重复输入
- **状态管理**：待发货 → 运输中 → 待取件 → 已取件 全链路跟踪，误点取件可恢复
- **数据持久化**：数据存储在本地 SQLite 数据库，随应用持久保存

### 订单自动采集

登录电商账号后一键同步在途订单，无需手动录入即可自动补齐取件码、运单号与驿站信息。

- **淘宝**：支持扫码登录（二维码由服务端本地渲染，登录凭证不外传）或粘贴浏览器 Cookie 两种方式；自动同步在途订单，提取运单号、取件码、快递公司、驿站、收件人及手机号
- **拼多多**：粘贴浏览器 Cookie 接入，自动分页同步待发货、运输中和待取件订单，过滤已签收及已完成订单
- **状态只前进**：待发货 → 运输中 → 待取件，已取件为终态，不会被采集覆盖
- **一键刷新**：手动刷新可拉取新快递、更新取件码与物流状态
- **账号管理**：管理页统一管理淘宝 / 拼多多账号，支持添加多个账号与批量同步

### 🖥️ 实时大屏展示

- **实时同步**：基于 SSE（Server-Sent Events）推送，新增 / 取件 / 删除即时刷新，多端同步
- **分组视图**：按「取件地址」或「取件情况」分组浏览
- **快速筛选**：全部 / 待取件 / 已取件一键切换
- **隐私保护**：展示页对收件人姓名、手机号自动脱敏
- **今日已取**：展示页的「已取件」列表与计数仅显示当天已取的包裹
- **管理入口**：展示页右上角的「管理」按钮或左上角 Logo 均可一键进入管理后台。飞牛网关环境下应用不暴露独立端口，管理页需经 `/app/pickup-codes/admin.html` 路径访问，该入口省去手动拼接路径的麻烦

### 🔒 安全与权限

- **管理后台密码保护**：可设置管理员密码，展示页免密访问，管理操作需鉴权
- **会话保持**：登录会话保持 12 小时

### 🛠️ 飞牛 fnOS 深度集成

- 支持应用商店安装向导（密码、会话时长、AI 配置可视化填写）
- 随系统开机自启、异常状态检测（start / stop / status 生命周期脚本）
- 通过 fnOS 统一网关（Unix Socket）反向代理访问，不对外暴露端口，支持应用图标与桌面入口

## 技术栈与架构

### 技术栈

| 层级 | 技术选型 | 说明 |
| --- | --- | --- |
| 运行时 | Node.js ≥ 18 | 后端服务运行环境 |
| 后端框架 | Express 5 | REST API 服务 |
| 数据库 | sql.js（SQLite WASM） | 零依赖嵌入式数据库，单文件持久化 |
| 实时通信 | SSE | 服务端事件推送，实时刷新展示页 |
| 前端 | 原生 HTML + JavaScript | 无需构建，开箱即用 |
| 样式 | Tailwind CSS（CDN） | 响应式界面 |
| AI 识别 | SiliconFlow 视觉大模型 API | 快递面单 OCR 结构化识别 |
| 订单采集 | 淘宝 / 拼多多 H5 接口 | 扫码或 Cookie 登录，自动同步在途订单与取件码 |
| 平台 | 飞牛 fnOS | manifest + 生命周期脚本打包为系统应用 |

### 架构概览

```text
┌──────────────────────────────────────────────┐
│                 浏览器端                      │
│   展示页 (/)  ←─SSE 实时推送──┐               │
│   管理页 (/admin.html) ──REST API──┤          │
└──────────────────────────────────────────────┘
                      │
                 Express 服务
              (app/server/server.js)
                      │
        ┌──────────┬──┴───────┬──────────────┐
        │          │          │              │
   REST API    SSE 推送   AI 识别转发     订单采集
  (packages)   (events)  (SiliconFlow) (淘宝/拼多多)
        │
   sql.js 数据库 (data.db)
```

- 服务端采用**无状态单进程**架构，所有数据经由 `db.js` 统一访问 SQLite
- 数据变更通过 `broadcast()` 向所有 SSE 客户端广播，实现多端实时同步
- 订单采集按订单号 / 运单号去重，状态只前进，避免重复导入与状态回退
- 支持 fnOS 网关前缀（`/app/pickup-codes`）自动剥离，同一代码可本地直跑或作为系统应用运行

## 环境要求

### 作为 fnOS 应用

- 飞牛 fnOS 系统（x86_64 / arm64 均可）
- 依赖 **nodejs_v22** 应用（安装时自动检查；应用直接调用其 Node 运行时，不要求该依赖处于运行状态）

### 独立运行（本地 / 普通服务器）

| 依赖 | 版本要求 |
| --- | --- |
| Node.js | ≥ 18.0.0 |
| npm | 随 Node.js 附带 |
| 网络 | 如需 AI 识别需可访问 `api.siliconflow.cn`；如需订单采集需可访问淘宝 / 拼多多 |

> 无需额外数据库服务，数据存储于本地文件 `data.db`。

## 安装步骤

### 方式一：fnOS 应用安装（推荐）

1. 在 [Releases](https://github.com/YUNXI-fi/Pickup-Code-Display/releases) 下载 `pickup.codes_x.x.x_all.fpk` 安装包
2. 打开 fnOS 桌面 → **应用中心** → **手动安装**，选择该 `.fpk` 文件
3. 按向导填写：
   - **管理密码**（留空则不启用）
   - **会话保持时长**（默认 12 小时）
   - **SiliconFlow API Key** 与 **AI 模型**（可选，用于面单识别）
4. 安装完成后，在桌面点击「取件码展示」图标即可访问展示页（经 fnOS 统一网关访问，不对外暴露端口，无法直接通过 `<IP>:3000` 访问）
5. 管理页入口：点击展示页右上角「管理」按钮或左上角 Logo 即可进入；也可在已登录飞牛桌面的浏览器中直接访问 `<飞牛面板地址>/app/pickup-codes/admin.html`，其中 `<飞牛面板地址>` 即你平时访问飞牛面板所用的地址（端口因人而异，以实际为准）

### 方式二：独立运行（开发 / 调试）

```bash
# 1. 进入服务目录
cd app/server

# 2. 安装依赖
npm install

# 3. 复制环境变量模板并修改
cp .env.example .env

# 4. 启动服务
npm start        # 生产运行
npm run dev      # 开发模式（文件变更自动重启）
```

启动后：

- 展示页：<http://localhost:3000>
- 管理页：<http://localhost:3000/admin.html>
- 局域网访问：`http://<本机IP>:3000`

## 配置说明

通过环境变量或 fnOS 安装向导配置，所有配置项见 `.env.example`：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 服务监听端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `ADMIN_PASSWORD` | 空 | 管理密码，留空则不启用鉴权 |
| `SESSION_DURATION_HOURS` | `12` | 登录会话保持时长（小时，1–720）。注：当前管理页会话固定按 12 小时写入，暂不随此配置变化 |
| `SILICONFLOW_API_KEY` | 空 | SiliconFlow API Key（AI 面单识别） |
| `SILICONFLOW_MODEL` | `Qwen/Qwen3.6-27B` | AI 识别使用的视觉模型（未配置时代码兜底为 `Pro/Qwen-VL-Chat-7B`） |

配置示例：

```bash
PORT=3000
ADMIN_PASSWORD=my-secret
SILICONFLOW_API_KEY=sk-xxxxxxxxxxxxxxxx
```

> 获取 SiliconFlow API Key：前往 <https://cloud.siliconflow.cn> 注册并创建密钥。
>
> 淘宝 / 拼多多账号不通过环境变量配置，而是在管理页的账号管理（右上角齿轮按钮）中登录或粘贴 Cookie。

## 使用指南

### 1. 展示页（大屏）

打开应用首页，即可看到所有待取件包裹：

- **切换分组**：「取件地址」按驿站/代收点归类展示；「取件情况」按待取/已取区分
- **筛选**：全部 / 待取件 / 已取件（已取件仅显示当天）
- **标记取件**：点击包裹卡片上的「取件」按钮，状态即时更新并同步到所有屏幕
- **进入管理页**：点击页面右上角「管理」按钮或左上角 Logo（fnOS 网关下对应 `/app/pickup-codes/admin.html`）

### 2. 管理页（后台）

访问 `admin.html`（fnOS 网关上为 `/app/pickup-codes/admin.html`，也可从展示页右上角「管理」按钮进入），首次访问需输入管理密码（若已启用）。

**手动添加快递：**

1. 填写取件码（必填）、快递公司、收件人、手机尾号、取件地址
2. 收件人 / 手机尾号 / 地址输入时自动弹出历史联想，可点击补全
3. 点击「添加」，新包裹将实时出现在展示页

**AI 识别添加：**

1. 表单为空时，底部按钮显示为「上传图片」，点击选择快递面单照片（每次一张）
2. 系统自动压缩并调用视觉模型识别，识别结果以标签形式展示；再次上传会以新结果替换现有标签
3. 点击标签切换查看，表单会自动填充对应包裹的信息，确认后点击「添加」入库（已添加的标签自动移除）

**管理操作：**

- 待取件包裹显示「取件」按钮，点击标记已取件；已取件包裹显示「未取」按钮，点击恢复为待取件
- 点击「删除」弹出确认框，确认后删除
- 顶部筛选按钮可切换 全部 / 待发货 / 运输中 / 待取件 / 已取件 列表
- 点击顶部「刷新」按钮：按已配置的渠道拉取新快递、刷新取件码并同步订单；未配置的渠道自动跳过，单个渠道失败不影响其他渠道

### 3. 淘宝 / 拼多多订单同步

在管理页右上角点击齿轮按钮（悬停提示「添加账号」）进入账号管理。

**添加淘宝账号：**

1. 点击「添加账号」→ 选择「淘宝」
2. 选择一种登录方式：
   - **扫码登录**：点击「扫码登录淘宝」，用手机淘宝「扫一扫」确认登录
   - **粘贴 Cookie**：浏览器登录 taobao.com 后按 F12 → Network → 任意请求 → 复制 Cookie（需包含 `_m_h5_tk`），粘贴后点击「保存 Cookie」
3. 保存成功后，「淘宝」状态显示为「Cookie 已配置」

**添加拼多多账号：**

拼多多暂不支持扫码登录，需在浏览器登录网页版后复制 Cookie（仅首次接入或登录失效时需要）。

1. 点击「添加账号」→ 选择「拼多多」
2. 按 F12 打开开发者工具，再按 `Ctrl+Shift+M`（Mac 为 `Cmd+Shift+M`）开启设备模拟，选择 **iPad** 等移动设备——网页版仅对移动端 UA 正常开放
3. 在设备模拟窗口中打开 `https://mobile.yangkeduo.com` 并登录（可用拼多多 App 扫码或手机号验证码）
4. 切到 **Network** 面板，刷新页面，点击任意一个 `mobile.yangkeduo.com` 请求（如 `orders.html`）→ **Headers → Request Headers**，复制 `Cookie:` 后的完整值
5. 粘贴回管理页输入框，点击「保存 Cookie」：
   - 必含字段：`PDDAccessToken`（登录凭证）与 `pdd_user_id`（用户标识），缺任一项会被拒绝并给出对应提示
   - 直接整段粘贴 `k=v; k=v; …` 即可，换行与多余空白会自动处理，无需手工整理
6. 保存成功后，「拼多多」状态显示为「Cookie 已配置」

> 常见提示含义：提示缺少字段 = 未登录成功或复制不完整（登录成功后 Cookie 才会包含 `PDDAccessToken`）；同步时报「拼多多登录态已失效」= Cookie 已过期，按上述步骤重新登录复制即可。

**同步订单：**

- 回到管理页，点击顶部「刷新」按钮，将按已配置的渠道拉取在途订单并刷新取件码（淘宝 / 拼多多可单独使用）
- 同一平台可重复添加多个账号，并分别显示备注与 Cookie 配置状态；点击对应账号的「更新」可更换 Cookie 和备注，点击「删除」可清除该账号的登录凭证

### 4. 操作示例

添加一个包裹并取件的完整流程：

```text
管理页填表 → 取件码: 6-2-3456，快递公司: 圆通，收件人: 张三，
手机尾号: 1234，取件地址: 菜鸟驿站(幸福小区店)
      ↓
点击「添加」
      ↓
展示页实时出现该包裹（按取件地址自动分组到「菜鸟驿站」）
      ↓
用户取件 → 展示页点击「取件」
      ↓
状态变为「已取件」，所有终端同步刷新
```

## API 一览

所有接口均挂载在 `/api` 下，管理类接口需携带 `x-admin-password` 请求头；管理页支持通过 `admin.html?pw=<密码>` 传入密码登录。

### 包裹与展示

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/packages` | 否 | 获取包裹列表（`?status=all` 返回全部，默认仅待取件） |
| POST | `/api/packages` | 是 | 新增包裹 |
| PATCH | `/api/packages/:id/pickup` | 否 | 标记已取件 |
| PATCH | `/api/packages/:id/restore` | 是 | 恢复为待取件 |
| DELETE | `/api/packages/:id` | 是 | 删除包裹 |
| GET | `/api/events` | 否 | SSE 实时事件流（create / update / delete） |
| POST | `/api/recognize` | 是 | AI 识别面单图片（base64） |
| GET | `/api/history?field=` | 否 | 历史联想（`recipient` / `phone` / `address`） |
| GET | `/api/check-password` | 否 | 校验管理密码 |

### 淘宝订单采集

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/express/status` | 是 | 查询淘宝账号配置与最近同步记录 |
| POST | `/api/express/cookie` | 是 | 保存淘宝 Cookie |
| DELETE | `/api/express/cookie` | 是 | 删除淘宝账号 |
| POST | `/api/express/qrcode` | 是 | 生成淘宝扫码登录二维码 |
| GET | `/api/express/qrcode/:sid` | 是 | 轮询扫码登录状态 |
| POST | `/api/express/sync` | 是 | 同步在途订单（新增 / 升级包裹） |
| POST | `/api/express/fill-codes` | 是 | 刷新待取包裹的取件码与物流信息 |

### 拼多多订单采集

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/pdd/status` | 是 | 查询拼多多账号配置 |
| POST | `/api/pdd/cookie` | 是 | 保存拼多多 Cookie |
| DELETE | `/api/pdd/cookie` | 是 | 删除拼多多账号 |
| POST | `/api/pdd/sync` | 是 | 同步待发货、运输中及待取件订单，过滤已签收/已完成订单 |

## 贡献规范

欢迎提交 Issue 与 Pull Request，参与贡献前请阅读以下规范：

1. **提交流程**
   - 先开 Issue 描述问题或需求，确认后再开发，避免无效 PR
   - Fork 仓库 → 新建功能分支 → 提交变更 → 发起 Pull Request
2. **代码规范**
   - 保持现有代码风格（无分号风格、2 空格缩进、单引号）
   - 不引入不必要的第三方依赖，优先使用 Node.js 原生能力
   - 提交信息使用简洁的英文描述，如 `feat: support batch import`
3. **测试要求**
   - 变更涉及 API 时，附上调用示例或自测结果
   - 确保 `npm start` 可正常启动，`data.db` 不影响首次运行
4. **文档同步**
   - 功能变更需同步更新 README 中对应章节
